## 2. Global Constraints — restated verbatim

These are what 23 commits of fix rounds were spent on. Violating any of them costs another round.

> **1.** NOTHING under `app/` may import from `src/`. `app/` is the new Nuxt tree; `src/` is legacy and gets deleted at the end of Phase 2. If a view being ported imports something still in `src/`, that dependency must ALSO move into `app/` (components → `app/components/`).
>
> **2.** Nuxt composables (`useRuntimeConfig`, `useNuxtApp`, `useRoute`, `useRouter`, `useCookie`, `useRequestURL`, `useHead`, `useSeoHead`, `useScreenSizes`) THROW "nuxt instance unavailable" if executed at MODULE SCOPE. Valid contexts: component setup, a composable invoked during setup, a Pinia state factory/getter/action, a plugin body, a Nitro handler. `import.meta.env` is a compile-time constant and was safe at module scope; `useRuntimeConfig` is NOT.
>
> **3.** Module-scope reactive state (`ref`/`reactive`/`computed`/`useMediaQuery`/`useTimestamp`) or module-scope object/array literals used as Pinia state are created ONCE PER SERVER PROCESS and shared across every concurrent SSR request. On a betting site that is a cross-user data-leak. They must be created inside a factory/setup.
>
> **4.** Pages that gain directory depth break their relative `../` imports. Rewrite those as `@/` (which aliases to `app/`).
>
> **5.** Nuxt auto-registers components with `pathPrefix:true`, so `app/components/foo/Bar.vue` registers as `FooBar`, and a redundant dir prefix is stripped (`cashout/CashoutModal` → `CashoutModal`). Name collisions are real and have already bitten this repo twice.

### Two derived rules that cost the same kind of round

**6. Deleting a `phase2Placeholders` entry deletes its `noindex` header with it.** `phase2NoindexRouteRules` (`nuxt.config.js:138-147`) is generated by looping over that array. Every ported page that should stay out of the index needs its own **permanent** `routeRules` entry — `{ ssr: false, headers: { "X-Robots-Tag": "noindex, nofollow" } }` — added in the *same commit* that removes the placeholder. `useSeoHead({ robots: "noindex,nofollow" })` is **not** a substitute for a client-rendered page: under `mode:"client"` / `ssr:false` Nuxt's `pageToClientOnly` returns `ServerPlaceholder` and the `<script setup>` never executes server-side, so no `<meta name="robots">` reaches the crawler. This is exactly what the comment at `nuxt.config.js:119-122` documents.

**7. Layout chrome double-renders unless `layout: false` is set.** `app/layouts/default.vue` is a verbatim port of the baseline `src/views/WithSibarAndBetslip.vue` (diffed — identical apart from `RouterView` → `<slot />`). It renders `HeaderLinks`, `Footer`, `MobileFooterV2`, `TheSidebar`, `SportsBetslipPanel` in all three responsive branches, **plus its own `<h1 class="sr-only">`**. Nuxt applies it whenever `definePageMeta` omits `layout`. Any view that was a **top-level** baseline route and renders its own `HeaderLinks`/`Footer` needs `layout: false`. Views that were **children of the `WithSibarAndBetslip` parent** want `layout: "default"` and should have their own chrome tags stripped.
> Do **not** copy `app/pages/promotions.vue` as the template — it sets `layout: "default"` *and* renders `HeaderLinks`/`Footer`/`MobileFooterV2` itself, so it double-renders chrome today. Fix it opportunistically.

### Routing wrinkles — concrete techniques

**1. `match-details` fused segment → `pages:extend` path rewrite.** The path `/sports/:sport/:country/:league/:matchSlug(.*)-:id` has **no Nuxt filename equivalent** — file-based routing cannot express a fused `slug-id` segment. Create the page file at any stable name (`app/pages/match-details.vue`) and in the same `pages:extend` hook that currently pushes placeholders, **find that page and rewrite `page.path`**:

```js
"pages:extend"(pages) {
  const md = pages.find((p) => p.file?.endsWith("app/pages/match-details.vue"));
  if (md) {
    md.path = "/sports/:sport/:country/:league/:matchSlug(.*)-:id";
    md.name = "match-details";
  }
  // ... remaining placeholders
}
```

### F.4 Static-vs-dynamic sibling ranking under `/virtual-games/`

`app/pages/virtual-games/[name].vue` shares its parent with **four static siblings** (`nai-league`, `nai-turbo`, `nai-virtual-jackpot`, `playon`) plus `index.vue`. ### F.5 `/ke/:pathMatch(.*)*` — **not a page port**

The assignment calls this "instant"; **there is no route named `instant` in the baseline.** The `/instant` routes are commented out (baseline 614-680) and replaced by two redirects to `/casino-home` (598-599). What actually lives at `/ke/:pathMatch(.*)*` is a **pure redirect with no name and no component** (baseline 606-613): it joins the `pathMatch` array and returns `{ path: "/" + rest, query: to.query, hash: to.hash }`, plus a sibling `{ path: "/ke", redirect: "/" }` at 605.

A catch-all `.vue` page (`app/pages/ke/[...pathMatch].vue`) is the **wrong shape** — it emits HTTP 200 with a client-side redirect, losing the 301 that indexed `/ke/*` URLs need (`docs/seo-cutover.md:4-9` says that prefix is indexed by Google and bookmarked by users). **Use a Nitro server route or middleware that `sendRedirect(event, target, 301)` preserving query string and hash.** Covered in Batch 0.2.

## 11. Batch G — Catch-all 404, and teardown

**Hard dependency: this batch is last.** A catch-all page swallows every path not yet registered.

### G.1 `not-found`

`src/views/NotFound.vue` (47 lines) → **`app/pages/[...slug].vue`** *or* **`app/error.vue`**. Correctly absent from `phase2Placeholders` (a catch-all placeholder would have swallowed every unregistered path).

Two viable targets with different semantics — **choose deliberately**:
- `app/pages/[...slug].vue` is the literal equivalent of the old vue-router catch-all and can carry `definePageMeta({ name: "not-found", layout: false })` — **but it returns HTTP 200 unless the page calls `setResponseStatus(event, 404)`.** Shipping it without that turns every dead URL into a **soft-404**, strictly worse for SEO than Nuxt's built-in behaviour.
- `app/error.vue` gets the correct status for free but cannot carry a route name.

Either way, set `robots: "noindex,nofollow"` — **the only baseline route that set `robots` explicitly.**
